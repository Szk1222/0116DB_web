产品简介

语音识别

自动语音识别（ASR，Automatic Speech Recognition）通过先进的深度学习技术，将自然语音精准转换成文本信息。支持一句话语音识别、实时语音识别、录音文件转写。适用于多个应用场景中，包括智能问答、智能质检、实时演讲字幕、访谈录音转写等场景，在金融、保险、司法、电商等多个领域均有应用。

一句话语音识别

对时长较短（一分钟以内）的语音进行识别，适用于较短的语音交互场景，如语音搜索、语音指令、语音短消息等，可集成在各类 App、智能家电、智能助手等产品中。

实时长语音识别

对不限时长的音频流做实时识别，达到“边说边出文字”的效果，内置智能断句，可提供每句话开始结束时间。可用于视频实时直播字幕、实时会议记录、实时法庭庭审记录、智能语音助手等场景。

录音文件转写

对用户上传的录音文件进行识别，可用于呼叫中心语音质检、庭审数据库录入、会议记录总结、医院病历录入等场景。

自学习技术

热词：在语音识别服务中，如果在您的业务领域有一些特有的词，默认识别效果较差的时候可以考虑使用热词功能，将这些词添加到词表，改善这部分词的识别结果。

自学习模型：支持您上传业务相关的文本语料训练自学习模型，可以在该业务领域中获得更高的识别准确率，比如司法、金融等领域。

语音合成

语音合成（TTS，Text To Speech）通过先进的深度学习技术，将文本转换成自然流畅的语音。标贝语音合成服务，有多种音色可供选择，支持音量、语速、语调调节。适用于智能客服、语音交互、有声阅读等场景。

产品优势

  • 持续深耕技术能力：兼顾了多级韵律停顿，达到自然合成韵律的目的，综合利用声学参数和语言学参数，建立基于深度学习的多重自动预测模型。
  • 多领域覆盖：在智能家居、车载、导航、金融、银行、保险、证券、运营商、物流、房地产、教育等众多领域积累了大量的词库，使标贝语音合成技术对各领域、各行业的词汇发音更准确。
  • 合成音听感自然逼真：经海量音频数据训练，使合成音真实饱满、抑扬顿挫、富有表现力，MOS 评分达到业内顶级水准。
  • 语音合成声音定制：为企业提供深度定制 TTS 声音的能力。通过先进的深度学习技术，用更少的数据量，更快速高效地为您定制个性化语音合成声音，将自然流畅的 TTS 声音带到服务或设备上。

适用场景

  • 智能客服：提供多行业多场景的智能客服语音合成能力，提高解答效率，提升客户满意度，降低呼叫中心人工成本。
  • 智能设备：为智能家居、音箱、车载和可穿戴设备等赋予一个最有温度的声音。
  • 有声阅读：让富有感染力的声音为您讲故事、读小说和播新闻，满足“懒人”的阅读需求。
  • 无障碍播报：无论是健全人还是残疾人，无论是年轻人还是老年人，将文字转成流畅动听的自然语言声音。

声音复刻

声音复刻基于自研的深度学习技术和迁移技术，让用户采集少量的语音数据，能够快速、低成本地定制一个新的音色，在声音相似度和声音的自然度上，都能够达到产品化的要求。可以满足家人陪伴、智能交互、在线教育、智能客服等场景对声音个性化的要求。

声音转换

声音转换（Voice Conversion），基于深度学习技术、表征学习和迁移学习，将用户输入的原说话人的声音转换成目标说话人的声音。在改变输出声音音色的同时，很大程度地保留了原说话人的语气、风格，让声音的生成多样化，更富有表现力和创造力。适用于智能客服、媒体娱乐、虚拟直播等不同的应用场景，满足不同人群对于声音创作以及声音音色稳定性输出的要求。

声纹识别

提供自研的声纹识别基本算法与声纹管理功能，仅通过声音就可以识别说话人身份，采集成本更低。通过标贝自主研发的强大的声纹算法引擎，实现声纹注册和声纹 1:1、1:N 对比验证服务，对说话人的声波特征进行提取和验证辨识，高准确率、低延迟。

基本概念

本章节整理调用语音服务前最常遇到的基础参数。建议在接入 ASR / TTS / 声音复刻等能力前，先确认音频采样率、采样位数、编码格式、声道和访问令牌策略，避免出现识别失败、合成效果异常或凭证泄露等问题。

接入前检查：音频数据的真实格式必须与接口参数一致。采样率、编码、声道任一项不匹配，都可能导致识别准确率下降、合成失败或返回不可用结果。

音频采样率（sample rate）

音频采样率是录音设备在一秒钟内对声音信号的采样次数，单位通常为 Hz。采样频率越高，声音还原越细腻，但传输和存储成本也会更高。

  • 语音合成服务常用 16000Hz 和 8000Hz 两种采样率；其中 8000Hz 多用于电话客服等窄带语音场景。
  • 语音识别服务同样需要在调用时声明采样率，音频数据与参数必须保持一致。
  • 如果原始音频高于 16000Hz，可先降采样到 16000Hz 后再发送；如果原始音频为 8000Hz，不要强行升采样，应选择 8000Hz 模型或对应参数。
采样率典型场景接入建议
8000Hz电话、呼叫中心、客服录音按窄带模型或接口参数传入，不建议升采样伪装成 16k。
16000HzApp 语音、会议、车载、智能硬件通用推荐值，兼顾识别效果与传输成本。

音频采样位数（sample size）

采样位数也称位深，用来描述每个采样点的幅度量化精度。位数越高，能够表达的声音动态范围越大。语音识别中常用 16bit 小端序音频，每次采样以 2 字节保存。

  • 8bit：每个采样点记录 256 个量化级别。
  • 16bit：每个采样点记录 65536 个量化级别，是语音接口中更常见的输入规格。

语音编码（format）

语音编码描述音频数据的存储与传输方式。它与文件后缀并不完全等同，例如 wav 文件头会声明音频数据的编码格式，内部数据可能是 PCM，也可能是其他编码。

概念说明
文件格式如 wav、mp3、m4a，更偏向文件容器或封装形式。
音频编码如 PCM、OPUS，决定音频样本的压缩与表达方式。
接口参数调用前应确认服务支持的编码，并让参数与真实数据一致。

声道（channel）

声道是录音时在不同空间位置采集到的独立音频信号数量。常见音频可分为单声道（mono）和双声道（stereo）。除录音文件识别等特定能力外，实时识别和一句话识别通常建议使用单声道音频。

  • 单声道 mono：一个音频通道，适合多数语音识别与合成服务。
  • 双声道 stereo：两个音频通道，如需接入仅支持单声道的接口，应先转换为 mono。

识别结果

不同接口返回识别结果的时机不同，接入时要按业务体验选择非流式或流式能力。

01非流式 API：音频发送完成后，一次性返回最终识别结果，适合短音频、录音文件和离线处理场景。
02流式 API：识别过程中持续返回中间结果，可实现“边说边出字”的连续上屏体验。
03最终结果：服务会在中间结果基础上持续修正，最后输出更稳定的整句文本。

例如一段语音最终识别为“你好标贝科技”，流式中间结果可能依次返回：

你
你好
你好标贝
你好标贝科技

访问令牌

访问令牌是访问语音服务的临时凭证，通常通过 client_id 与 client_secret 换取，并带有有效期控制。业务侧应避免在客户端直接暴露密钥。

  • 默认有效期可按平台规则配置，常见场景为 24 小时有效。
  • 移动端或浏览器端应用建议从业务服务端获取令牌，再下发给客户端调用。
  • 不要把 client_secret 写入 App 包、前端代码或公开仓库。
推荐链路：业务服务端保存密钥并换取访问令牌，客户端只拿到短期有效 token。这样即使客户端包体或页面代码被查看，也不会泄露长期密钥。

登录

进入产品地址后，可使用短信、密码或微信方式登录。首次登录后建议先确认账号主体信息与认证状态，再创建应用。

创建新应用

登录后进入【首页概览】，开发者可以创建多个应用。应用可覆盖一句话识别、长语音识别、录音文件识别、短文本合成、离线合成、长文本合成等服务，并可根据需求进行用量、音色、并发等接入试用。

  • 未认证商户只能创建 1 个应用以供试用。
  • 企业认证商户最多创建 13 个应用。
  • 个人认证商户最多创建 5 个应用。
应用隔离：每个应用都是独立的，服务量不共享，调用数据也单独统计，便于开发者按产品、业务线或环境核算调用成本。

选择服务

进入【已创建的应用】后，在左侧选择需要调用的 AI 技术服务，右侧会展示对应服务页面概览，可用于查询用量、管理套餐、购买服务量、自主获取授权和配置预警。

获取 Key&Secret

在服务的【授权管理】中获取对应参数，并用于服务端开发配置。随后通过 Key 与 Secret 换取访问令牌 token，再使用 token 调用具体语音能力。

01进入指定应用，选择需要接入的服务。
02打开服务 / 授权管理，复制或查看 Key 与 Secret。
03在业务服务端换取访问令牌，并把短期 token 下发给调用端。

SSML 标签

SSML 是一种基于 XML 的语音合成标记语言，用于在合成文本中控制音色、文件类型、采样率、码率、语速、音调、音量、背景音乐、停顿、分词、别名、读音和场景读法等效果。

概述

SSML 文本需要以 <speak> 作为根标签。使用 SSML 后，标签内指定的参数优先级高于接口请求参数；SSML 标记语言与标贝 XML 标签不可混用。

<speak voice="Jingjing" speed="5" volume="6">
  欢迎使用语音合成服务。
</speak>

使用方式

  • 将完整 SSML 文本作为待合成文本提交，鉴权、请求地址和音频返回方式仍按对应语音合成接口说明执行。
  • 普通语音合成任务只包含一个 <speak></speak> 根标签；长文本合成可包含多个成对的 <speak></speak> 标签。
  • 当文本中连续使用多个 SSML 标签时，标签之间不要插入多余空格。
  • 目前旧版文档标注为仅支持中文音色；不同发音人对部分标签的支持效果可能不同，建议以实际合成结果为准。

time时间读法。<say-as interpret-as="time">2:00pm</say-as>
currency货币读法。<say-as interpret-as="currency">8000000.00RMB</say-as>
measure度量衡读法。<say-as interpret-as="measure">45m12cm</say-as>

综合示例

<speak voice="Jingjing" speed="5" volume="6">
  <s>请找一个舒适的地方坐下</s>
  <break time="500ms"/>
  慢慢放松呼吸。
  订单号是 <say-as interpret-as="characters">A1024</say-as>。
</speak>

注意事项

  • SSML 标记语言和标贝 XML 标签不可混用。
  • 使用 SSML 后，以 SSML 标签内选定参数为准，优先级高于接口请求参数。
  • 长文本任务若多个 <speak> 标签使用不同音色，接口参数与标签内音色的采样率需保持一致。
  • 文本内容包含 XML 特殊字符时需要转义：" 转为 &quot;，' 转为 &apos;，& 转为 &amp;，< 转为 &lt;，> 转为 &gt;。
  • 背景音乐或提示音资源应确保可访问，并由接入方自行确认版权与使用权限。

语音合成时间戳功能

语音合成时间戳功能可在输出音频的同时返回文本在音频中的时间位置。旧站文档按使用场景分为音子级别时间戳和字级别时间戳，主要用于虚拟人口型驱动、视频配音字幕、有声书朗读等场景。

功能介绍

时间戳功能分为两类：音子级别时间戳用于获取音子边界信息，常见于口型驱动；字级别时间戳用于获取每个汉字或英文单词的起止时间，常见于字幕对齐。

  • 只有支持音子级别时间戳的音色可以使用对应能力，具体以发音人列表标注为准。
  • 长文本任务中如使用多个发音人，所选音色都需要支持音子或字级别时间戳。
  • 开启时间戳后，响应结果结构会发生变化，需要按下文说明解析音频和时间戳信息。

短文本 RESTful API 参数

RESTful 接口通过 interval 和 enable_subtitles 开启时间戳能力。字级别时间戳需要与 interval=1 一起使用。

参数名称是否必填名称说明
interval否音子边界时间戳0 关闭音子级别时间戳；1 开启音子级别时间戳。
enable_subtitles否字级别时间戳0 关闭字级别时间戳；1 开启字级别时间戳，需同 interval=1 一起使用。
params = {
    "access_token": access_token,
    "domain": "1",
    "language": "zh",
    "voice_name": "Jiaojiao",
    "text": "标贝科技",
    "audiotype": "6",
    "interval": "1",
    "enable_subtitles": "1"
}

RESTful 响应结果

RESTful 接口需要先检查 HTTP 响应头 Content-Type：如果以 audio 开头表示合成成功；如果返回 application/json 表示合成出现错误。

开启时间戳后，成功响应的音频数据前部会携带时间戳结构。旧站示例中使用前 4 字节读取 JSON 长度，再解析时间戳 JSON，最后把剩余字节保存为音频。

字段名类型描述
dataobject时间戳信息。
err_msgstring错误信息，成功时通常为 succ。
err_noint错误码。
log_idint日志 ID。
snstring系统内部使用信息。

时间戳字段

字段名说明
interval-info音子级别时间戳，例如 b=0.072346&iao=0.238304。
interval-info-x音子附加信息，例如 L=1&T=1。其中 L 表示语言种类，T 表示 interval 类型。
interval-subtitles字级别时间戳，返回结果是 Base64 编码，需要解码后使用。
subtitles_listinterval-subtitles 解码后的时间戳列表。

T 的取值含义：0 默认值，1 声母，2 韵母，3 儿化韵母，4 英文，5 #3 静音。

字级别时间戳结构

interval-subtitles 解码后包含 subtitles_list，其中每个句子对象包含原句文本和 subtitles 明细。

字段名类型描述
textstring句子级别文本。
subtitleslist当前句子的时间戳明细。
begin_indexint文本对应当前句中的起始索引。
begin_timeint文本对应音频中的起始时间戳，单位毫秒。
end_indexint文本对应当前句中的结束索引。
end_timeint文本对应音频中的结束时间戳，单位毫秒。
prosodystring停顿类型，如 SP0、SP1、SP2、SP3。
{
  "subtitles_list": [{
    "text": "标贝科技",
    "subtitles": [
      {"begin_index": 0, "begin_time": 0, "end_index": 2, "end_time": 238, "prosody": "SP0", "text": "标"},
      {"begin_index": 3, "begin_time": 238, "end_index": 5, "end_time": 409, "prosody": "SP0", "text": "贝"}
    ]
  }]
}

短文本 WebSocket API

WebSocket 接口同样通过 tts_params.interval=1 和 tts_params.enable_subtitles=1 开启时间戳。开启后，时间戳信息会保存在响应 data.subtitles_list 中。

由于时间戳信息通常在整句音频生成完毕后给出，并非所有数据包都包含 subtitles_list，客户端应先判断字段是否存在，再读取时间戳。

  "access_token": "ACCESS_TOKEN",

    "language": "ZH",
    "voice_name": "beixi",
    "audiotype": "4",
    "domain": "1",
    "text": "BASE64_TEXT",
    "interval": "1",
    "enable_subtitles": "1"
  }
}
